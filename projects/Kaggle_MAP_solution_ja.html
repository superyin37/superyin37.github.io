一、タスク概要

本コンペは、数学問題に対する生徒の選択肢と自由記述の説明から、 生徒が持つ理解状態または誤概念を Category:Misconception として予測するタスクである。 評価指標は MAP@3 で、各サンプルに対して上位3件のラベルを提出する。

入力項目例
QuestionTextWhat fraction of the shape is not shaded?
MC_Answer1/3
Correct?Yes
StudentExplanationThere are 3 unshaded parts out of 9, so it is one third.

この入力から、以下のような提出行を生成する。

row_id,Category:Misconception
36696,True_Correct:NA True_Neither:NA False_Neither:NA

実装上は 65 クラス分類として扱い、各モデルの確率上位候補を使って最終的な上位3ラベルを決める。

二、全体アプローチ

方針は、複数の LLM 分類器で候補確率を出し、最後に重み付きアンサンブルで MAP@3 に最適化することである。 モデルごとに得意な表現や誤り方が異なるため、単一モデルの top-3 では拾い切れない候補を相互に補完する。

モデルサイズ学習方式役割
Gemma2-9B-IT9BLoRA安定した分類ベースライン
Qwen3-8B8BFFTフルファインチューニングによる別視点の候補生成
DeepSeek-Math-7B7BLoRA数学的推論に強い補助モデル
Hunyuan-7B-Instruct7BLoRAモデルファミリーの多様性を追加

三、データ前処理

前処理の目的は、元データを LLM が理解しやすい一つのテキストに変換し、 同時に提出ラベルと同じ Category:Misconception 空間を安定して再現することである。

1. ラベルを結合する

Category と Misconception を結合し、65 種類の分類ラベルを作る。 Misconception が空の場合は NA として扱う。 

train["Misconception"] = train["Misconception"].fillna("NA")
train["target"] = train["Category"] + ":" + train["Misconception"]
train["label"] = LabelEncoder().fit_transform(train["target"])

2. 選択肢が正答かどうかを推定する

テストデータには正答フラグが直接含まれないため、訓練データから QuestionId ごとの正答選択肢を推定し、各行に Correct? 特徴量として付与する。 これは生徒の説明を読む前に、回答そのものが正しいかをモデルに伝える重要な情報である。 

idx = train["Category"].str.split("_").str[0] == "True"
correct = train.loc[idx].copy()
correct["count"] = correct.groupby(["QuestionId", "MC_Answer"])["MC_Answer"].transform("count")
correct = correct.sort_values("count", ascending=False).drop_duplicates("QuestionId")
correct = correct[["QuestionId", "MC_Answer"]].assign(is_correct=1)

3. モデル入力テキストを作る

最終的な入力は、問題文、選択肢、正答性、生徒説明を同じ順序で結合した短い prompt-like テキストである。 訓練時と推論時で形式を揃えることが、ラベル順序の再現と同じくらい重要である。 

Question: {QuestionText}
Answer: {MC_Answer}
Correct? {Yes/No}
Student Explanation: {StudentExplanation}

4. 推論用の中間候補を保存する

各モデルは 65 クラス全体の logits を出すが、アンサンブルではファイルサイズと処理速度を考えて 上位25候補とその確率を保存する。 

row_id, top_classes, prob_0, prob_1, ..., prob_24

四、モデルのファインチューニングと設定確認

リポジトリ内で確認できる学習設定はモデルごとに粒度が異なる。 DeepSeek と Qwen3-8B は学習 notebook から具体的な設定を確認できる一方、 Gemma2 と Hunyuan は最終推論 notebook では既存 LoRA adapter の読み込みが中心である。

五、推論パイプライン

  • Gemma2 は単独 GPU で推論し、top-25 のクラスと確率を保存する。
  • Qwen3 と DeepSeek は 2 GPU に分けて並列推論する。
  • Hunyuan は新しい Transformers 依存関係を読み込んだ後、同じ形式で推論する。

すべてのモデル出力を同じ列形式にそろえることで、後段のアンサンブルをモデル非依存にしている。

六、アンサンブル戦略

最終スコアは単純平均ではなく、モデル重み、モデル間の一致、単一モデルの高信頼候補を組み合わせて計算する。 

final_score = 0.6 * weighted_probability
            + 0.3 * agreement_bonus
            + 0.1 * confidence_bonus
要素意味
weighted_probabilityモデルごとの確率に重みを掛けた基本スコア
agreement_bonus複数モデルが同じラベルを候補に出した場合の加点
confidence_bonusあるモデルが特に高い確率を出した候補を保護する加点

実装上の重みは DeepSeek=1.2、Gemma=1.1、Qwen3=0.9、Hunyuan=1.1 としている。

八、改善方向

  • クラス空間の削減: 正答性は高精度に推定できるため、65 クラスを直接解くモデルに加えて、Correct / Neither / 35 種の Misconception から成る 37 クラスモデルを併用する。
  • 出力空間の制限: QuestionId ごとに訓練データで出現した Misconception を候補集合として持ち、未出現候補は確率を下げる。完全にゼロにするより、soft mask の方が未知パターンに強い。
  • 長尾クラスの補強: 特に True_Misconception のような少数かつ誤分類されやすいケースを、既存の False_Misconception から選択肢だけ変えて増強する。
  • 表現ゆれのデータ拡張: 生徒説明を意味を保ったまま言い換え、短文、スペルミス、曖昧表現を含むデータを増やす。
  • 検証設計の改善: 類似した StudentExplanation が train/validation にまたがらないよう、StratifiedGroupKFold を使って過度に楽観的な CV を避ける。
  • 二段階 reranking: 既存 ensemble の top-10 または top-25 を候補にし、Qwen3-Reranker 系モデルで Yes/No 判定として再順位付けする。

1. Task Overview

The competition asks us to infer a student's understanding or misconception from a math question, the selected answer, and the student's written explanation. The submission target is Category:Misconception, evaluated with MAP@3.

Input fieldExample
QuestionTextWhat fraction of the shape is not shaded?
MC_Answer1/3
Correct?Yes
StudentExplanationThere are 3 unshaded parts out of 9, so it is one third.

The model produces a top-3 submission row like this:

row_id,Category:Misconception
36696,True_Correct:NA True_Neither:NA False_Neither:NA

The implementation treats the task as 65-class classification and then combines model candidates for the final top-3 labels.

2. Overall Approach

The solution uses multiple LLM classifiers to produce candidate probabilities, followed by a weighted ensemble optimized for MAP@3. The goal is to combine different model families and training styles so that hard labels missed by one model can still be recovered by another.

ModelSizeTraining MethodRole
Gemma2-9B-IT9BLoRAStable classification baseline
Qwen3-8B8BFFTFull fine-tuning based candidate generation
DeepSeek-Math-7B7BLoRAMath reasoning oriented support model
Hunyuan-7B-Instruct7BLoRAAdditional model-family diversity

3. Data Processing

Data processing has two goals: reproduce the official label space and convert each row into a compact text input that an LLM classifier can read consistently.

1. Build the target label

Category and Misconception are joined into the same label format required by the submission. Missing misconception values are normalized to NA. 

train["Misconception"] = train["Misconception"].fillna("NA")
train["target"] = train["Category"] + ":" + train["Misconception"]
train["label"] = LabelEncoder().fit_transform(train["target"])

2. Infer answer correctness

The test set does not directly provide whether the selected answer is correct. We infer the correct option for each QuestionId from training rows whose category starts with True, then merge that signal back as a feature. 

idx = train["Category"].str.split("_").str[0] == "True"
correct = train.loc[idx].copy()
correct["count"] = correct.groupby(["QuestionId", "MC_Answer"])["MC_Answer"].transform("count")
correct = correct.sort_values("count", ascending=False).drop_duplicates("QuestionId")
correct = correct[["QuestionId", "MC_Answer"]].assign(is_correct=1)

3. Format the model input

Each row is serialized with the same field order for training and inference. This helps the model distinguish a wrong answer with good reasoning from a correct answer with flawed reasoning. 

Question: {QuestionText}
Answer: {MC_Answer}
Correct? {Yes/No}
Student Explanation: {StudentExplanation}

4. Save intermediate candidates

Each model predicts over 65 classes, but the ensemble stores only the top-25 candidates and their probabilities for faster downstream merging. 

row_id, top_classes, prob_0, prob_1, ..., prob_24

4. Model Fine-Tuning and Configuration Check

The repository exposes different levels of detail for each model. DeepSeek and Qwen3-8B have training notebooks with explicit settings. Gemma2 and Hunyuan are mainly loaded as prebuilt LoRA adapters in the final inference notebook.

5. Inference Pipeline

  • Gemma2 runs on a single GPU and saves top-25 class probabilities.
  • Qwen3 and DeepSeek run in parallel on two GPUs.
  • Hunyuan runs with the same output format after loading the required Transformers version.

Normalizing all outputs into the same schema keeps the ensemble logic independent from individual model code.

6. Ensemble Strategy

The final score is not a plain average. It combines model weights, agreement across models, and high-confidence single-model predictions. 

final_score = 0.6 * weighted_probability
            + 0.3 * agreement_bonus
            + 0.1 * confidence_bonus
ComponentMeaning
weighted_probabilityBase probability score after applying model weights
agreement_bonusBonus when several models include the same label in their candidate lists
confidence_bonusBonus that protects labels with very high confidence from a single model

The implemented model weights are DeepSeek=1.2, Gemma=1.1, Qwen3=0.9, and Hunyuan=1.1.

8. Improvement Directions

  • Reduce the class space: Add a 37-class model over Correct / Neither / 35 misconceptions, then map it back with answer correctness and ensemble it with 65-class models.
  • Constrain the output space: Build a QuestionId to possible misconception map and down-weight unseen candidates. A soft mask is safer than setting probabilities to zero.
  • Improve long-tail coverage: Augment rare and confusing cases such as True_Misconception by changing only the selected answer while preserving the explanation and misconception label.
  • Augment expression diversity: Generate paraphrases, shorter explanations, spelling noise, and ambiguous wording while preserving the original meaning.
  • Use stricter validation: Apply StratifiedGroupKFold grouped by normalized StudentExplanation to avoid overly optimistic validation scores.
  • Add a second-stage reranker: Use the current ensemble top-10 or top-25 as candidates and rerank them with a Qwen3-Reranker style Yes/No model.

9. Environment and Reproducibility

  • Final inference: Transformers 4.56.1 family, PEFT, PyTorch, FP16/BF16
  • DeepSeek training notebook: transformers 4.41.2, peft 0.10.0, torch 2.6.0, torch_xla TPU
  • Inference environment: Kaggle GPU, running models sequentially or in parallel
