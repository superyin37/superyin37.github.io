# 建築設計企画支援AIシステム

**殷 晗陽**  
**担当:** 企画設計 / システムアーキテクチャ / コア実装

---

## 1. 企画概要

### 背景と企画意図
建築設計の企画初期段階では、設計者が建築事例、法規、設計ガイドライン、過去資料を横断的に参照しながら、コンセプト立案と提案資料作成を進める必要がある。一方で、情報はPDF・CAD図面・社内資料に分散しており、必要箇所の探索や照合に多くの時間がかかっていた。

特に課題だったのは、①建築基準や事例検索の非効率性、②企画立案の属人化、③PPT作成工数の大きさ、の三点である。そこで、情報探索・企画生成・成果物生成を一つの業務フローとして接続するAIシステムを企画した。

### 目的と設計方針
目的は、設計者が企画初期に必要とする知識検索、要件整理、企画案作成、資料化を一つのUI上で完結できるようにすることである。単なるチャットボットではなく、設計実務の前工程を支援する業務基盤として構成した。

- 知識の鮮度と出典提示が重要なため、学習済み知識に依存するのではなく、検索結果を根拠として回答できるRAGを中核方式として採用した。
- 入力形式が異なるため、テキストQA、対話型企画生成、CAD画像からの基準照合を独立モジュールとして設計し、保守性と機能ごとの拡張性を確保した。

### 私の担当範囲
本プロジェクトでは、企画と実装の両方に深く関与した。業務要件の整理からシステム分割方針の策定、主要モジュールのAPI化、クラウド配置まで一貫して担当した。

- **建築知識RAG検索システム**：検索パイプライン設計、Vector DB構築、FastAPI API実装、Dockerデプロイを主担当。
- **CAD建築基準検索システム**：OCR解析、基準番号抽出アルゴリズム、API実装、クラウド配置までを単独担当。
- **建築企画生成システム**：要件整理フロー、Promptテンプレート、PPT生成ロジックの設計を共同担当。

### 成果と技術的工夫
成果として、建築知識の検索効率化、CAD図面からの基準照合自動化、企画PPTの半自動生成を実現し、設計者の探索・整理・資料化の一連の負荷を削減した。モジュール分離により、将来的な知識ベース追加や生成機能拡張にも対応しやすい構成とした。

- **RAG精度向上**：Embedding検索で候補を広く取り、Cross-Encoderで再ランキングする二段構成により、法規表現の揺れに強い検索を実現。
- **OCR精度向上**：低解像度図面や手書き風表記に対応するため、OCR結果を正規表現とLLM補正で後処理し、基準番号抽出の安定性を改善。
- **今後の課題**：知識ベース更新の自動化、ログベース評価の強化、PPT生成品質のさらなる標準化。

## 2. アーキテクチャ概要

### 処理フロー
ユーザー入力は主に ①設計質問、②企画要件、③CAD図面画像 の3種類である。FrontendからFastAPIに送られ、用途に応じて各AIモジュールへ振り分ける。

- **RAG検索サービス**：Embedding、Vector Search、Cross-Encoder Rerank、LLM回答生成
- **CAD基準解析サービス**：画像一時保存、OCR、番号抽出・LLM補正、PDFページ照合
- **企画 / PPT生成サービス**：要件構造化、コンセプト生成、章立て生成、python-pptx 出力

### クラウド構成
- **Frontend / UI**：Web UI、対話・アップロード、結果表示
- **API / Orchestrator**：FastAPI、ルーティング、セッション管理
- **AWS S3**：PDF・画像・PPT保存
- **PostgreSQL**：メタデータ管理
- **Vector DB**：文書埋め込み保持
- **LLM / Embedding API**：回答生成・埋め込み推論

### 運用・セキュリティ
クラウド構成は AWS を前提とし、FastAPIサービスは EC2 上の Docker コンテナとして運用した。PDF・画像・生成成果物は S3 に保存し、メタデータは PostgreSQL、検索用埋め込みは Vector DB に保持した。

運用面では、コンテナ化による再現性確保、サービス単位の分離、ログ監視と再起動容易性を重視した。セキュリティ面では、社内業務利用を前提に、ファイルをストレージ側で分離し、API経由でのみ処理する構成を採用した。認証認可や詳細な権限制御は、全社基盤側に依存する前提で設計している。
